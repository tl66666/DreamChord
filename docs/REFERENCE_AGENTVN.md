# AgentVN 参考与取舍

参考对象：<https://github.com/aqualite2370/AgentVN-Editor>、<https://agentvn.space/>，核对日期：2026-08-17。

## 借鉴并落地

AgentVN 把“长文本 -> 结构化场景 -> 可运行作品”作为明确链路，并用 Schema 约束模型产物。DreamChord 本次引入共享 `SceneBlueprint`：本地草稿导入会先校验场景标题、地点和每条叙事/对白/选项节拍；模型创作任务新增 `create_scene_blueprint` 受限工具。蓝图校验通过后才会进入既有 StoryPatch、图校验和作者审批链路。

这比让模型直接把正文拼成节点操作更适合 DreamChord：编辑器、播放器和 Agent 已共用故事图与补丁协议，不需要重建另一套运行时。

## 已落地与后续可借鉴

1. 长篇导入任务已落地：正文按章节和安全字符块拆分，使用 Prisma 持久化检查点，支持暂停/继续/取消/失败块重试和真实进度。任务完成后仍进入 SceneBlueprint 与作者确认流程。
2. 作品发布包：在现有项目备份格式基础上增加只读发布清单与播放入口，先保持 Web 可运行，不为此引入桌面运行时依赖。
3. 叙事记忆评测：把客观事实变更、角色主观记忆和检索正确率加入 Agent 回归集；先评测现有六类记忆，再决定是否增加向量检索和情绪衰减。

## 不直接照搬

- 不引入 Python 后端、Tauri 或双运行时：DreamChord 当前 React/Express/Prisma 结构已经覆盖编辑、预览、备份和素材工作流，重写会扩大维护成本。
- 不默认开放 MCP、Shell、浏览器、文件系统或任意网络工具：故事创作需要项目和素材边界，所有写入仍应走业务工具、校验、预览和作者审批。
- 不把复杂记忆衰减或向量库包装为“更智能”：没有针对角色一致性、伏笔、事实冲突的评测集之前，优先保证现有记忆的可解释性、可确认性和可撤销性。
