# DreamChord Agent 控制平面

DreamChord 的 Agent 不是一个拥有任意电脑权限的通用聊天机器人，而是一个面向故事项目的受限创作协作者。它能读取项目资料、检索记忆、分析故事图、准备素材候选、生成剧情补丁和角色配音计划；所有会改变作品的动作都必须经过作者确认。

## 为什么不直接引入 Hermes Agent

NousResearch/hermes-agent 面向通用桌面/CLI 自动化，能力边界包含 Shell、浏览器、文件系统和 MCP 等广泛权限。DreamChord 的核心约束是项目级隔离、素材归属、剧情版本、可撤销写入和作者审批，因此直接嵌入 Hermes 会让权限模型过宽，也无法自然映射到章节、场景和镜头卡。

DreamChord 借鉴 Hermes 的四个思想：Provider 抽象、可见的运行状态、工具权限分级、失败恢复与审计回执；执行器、数据模型和审批流程仍由 DreamChord 自己控制。

## 工具权限

| 权限 | 典型工具 | 默认行为 |
| --- | --- | --- |
| 读取 `read` | 读取项目简介、章节、场景、记忆、素材 | 自动执行，不修改项目 |
| 准备 `prepare` | 处理立绘/CG/背景、生成角色配音计划 | 生成候选，作者接受后才入库 |
| 提案 `propose` | 创建剧情补丁 | 预览差异、校验通过后等待作者应用 |
| 校验 `validate` | 分析故事图、校验补丁 | 自动执行，只返回问题 |

每次工具调用都会写入时间线回执，包含工具、权限类别和是否需要作者确认。Agent 不具备任意 Shell、浏览器、SQL 或任意 HTTP 工具。

## 记忆与审批

记忆按 `canon`、`character`、`plot`、`decision`、`preference`、`artifact` 分层。模型提出的新记忆先保存为 `suggested`，作者在记忆中心确认后才变为 `active`；遗忘不会删除历史，而是标记为 `forgotten`。剧情补丁、素材候选、记忆建议和声音方案分别拥有独立的作者确认点。

## 运行回执

每次 AgentRun 的 `usage` 会记录：

- 执行模式：本地、模型或模型失败后的本地降级；
- Provider 与模型名称；
- 实际工具调用次数与工具清单；
- 产生的待确认记忆数量；
- 是否生成剧情补丁、是否发生降级。

前端时间线同时展示当前模型、执行模式、工具次数和待确认记忆，作者可以知道 Agent 做了什么、为什么需要确认，以及最终是否写入作品。

## 无 API Key 时

本地助手负责确定性任务：读取项目、检查结构、把用户草稿转换为可播放镜头卡、选择已有素材、生成角色配音计划和素材提示词。开放式长文本创作需要配置 Provider；模型请求失败时，动作任务会自动转入本地安全降级，仍然只生成审批草案，不会静默改稿。
