# 《请让这幅画老去》序章

本轮把审核通过的文学幻想主案制作成可玩的序章《多出来的一把椅子》。全篇按章节继续创作，目前没有发布空白的后续章。

2026-11-03叙事修订：补写以入场券为起点的第一人称开场，将动作、观察、内心反应和有明确来源的文学互文穿入演出。完整定稿见下方链接，旧私人副本不会自动改写。

## 体验入口

启动应用后，在首页点击「试玩官方示例」，或访问 `/play/dreamchord-paint-prologue`。默认中文字幕、日语配音；初次播放不需要启动模型、输入密钥或等候现场生成。字幕与声音可以分别切换；本序章预录仅提供日语，不能把中文轨道标成已就绪。

读完点击「带入工作台，写下下一句」。未登录先登录，随后创建自己的私有副本，并定位到夏禾的下一句。场景已回到夜间工房，立绘、原有对白、配乐与角色绑定都会保留。重复请求不会创建多份；不会改变官方作品或其他人的作品。

## 剧情与演出

程见为朋友的小戏修椅子。夏禾想让他坐下来，好好看一次自己的演出；许野在意那八位观众是否真的喜欢他的戏。散场以后，椅子左后腿的新补木消失，只留下原来蛀空的断口和地上的木屑。

现在从夏禾写在票背面的“七点，第一排。今天不许帮忙”开始。程见先是观众，才是临时帮手；让座之后他仍可以添椅，却又接过幕布，逐渐错过了演出。散场后的道具椅因此成为真正属于他的第九座。修理的快乐与接受他人的邀请都被保留。

《银河铁道之夜》关于真正幸福的问句作为题记，由本作据日文自译。《艺术家》出现在许野的旧书和未完成改编稿中，长久悲哀与短暂快乐的问题暂时留在舞台动作里；原著概述与本作原创改编痕迹明确区分。入场券、半幅海景布和深色补木在后文都有具体回收，没有用旁白给每件道具宣布象征意义。

一个行动选择分别走向「对台词」或「整理道具」，之后汇合。序章有一个完整收尾与下一章悬念，不伪装成多结局长篇。故事通过人物行动、道具与时间顺序埋线，不在对白里解释全部世界规则。

- [中文阅读稿](story/paint/reading.zh.md)：不带节点编号，正文按对台词路线连续展开，另一分支附在后面。
- [正式中日文本](story/paint/00-prologue.md)：与图谱同步，包含两条分支。
- [全篇创作设定](superpowers/specs/2026-11-02-paint-story-design.md)：有后续章节与世界真相，包含剧透。
- 正式数据：`packages/story-domain/src/paintPrologue.ts`（演出）、`paintNarration.ts`（中日叙述）、`paintLines.ts`（固定配音对白）。

## 声音、美术和来源

59句日语对白（含个人副本的起始句），共约295秒；叙述保持静默。4个角色各绑定固定音色，参考分日常与认真两种，不要求用户一句句选人。初始对白使用已准备的音轨；续写时按既有自动配音流程，在后台生成变化的片段。实际音频仍需要按台词合成，用户无需逐句操作。

Qwen3-TTS 生成原创合成参考，GPT-SoVITS v2ProPlus 用参考生成本次全部正式对白。没有借用商业游戏演员录音，没有声称训练了专属权重。少量短句定向重录，旧版本、种子、实际发音文本与处理参数保留。59条音轨与当前日文、WAV/OGG SHA、解码、时长和削波检查一致；ASR只辅助查错，**尚未完成人耳听感验收，不能据此承诺真人级或日语表演自然度**。

声音来源与重现说明在 `assets/voice-packs/paint-prologue/README.md`，技术报告在同目录 `technical-review.json`。参考 WAV 为角色参考，不是训练后的模型权重。

10张角色表情立绘，由内置生图模型生成原创素材。三位主要角色有平静、微笑、认真；陆青有平静立绘。角色原图为1024×1536真透明全身像，播放器沿用半身构图。本次新增居室、书与票根、半幅海景舞台3张叙事图；素材包共有9张背景/特写（含保留的旧舞台），正文使用其中8张。背景保留完整宽幅构图，发布为1920×1080 WebP；封面采用开场居室。原图、提示词记录与哈希在 `source-assets/paint-prologue/`。

配乐：TERNOX，CC0，取其现有曲目用于午后工房与散场余韵。[原作者许可](https://ternox.itch.io/vn-music)。音效：OtoLogic，CC BY 4.0，含轻木质碰撞、翻纸和小规模掌声；木声为竹木道具的实录foley，掌声为单人实拍错时叠加，不能描述成八人现场实录。[原作者条款](https://otologic.jp/free/license)。剧情尾部用停乐和静默呈现异常。发行时保留 TERNOX / OtoLogic 署名。

运行曲目与音效的来源、处理、时长、SHA在 `apps/web/public/assets/audio/paint-prologue/*-credits.json`，源文件与许可记录在 `assets/audio-packs/paint-prologue/`。

## 安装、验证与后续维护

```sh
pnpm demo:paint:seed
pnpm demo:paint:upgrade
pnpm test:paint
pnpm demo:paint:script
node scripts/export-paint-script.mjs --docs
node scripts/export-paint-script.mjs --reading
```

安装命令只创建缺失的官方项目；已存在的作品完整保留，不重置数据库。`demo:paint:upgrade` 是本次明确的旧版→新叙事版升级：仅固定官方ID、原demo作者、公开发布、内容指纹与发布v1完全一致时才事务更新；作者改过、私人副本或其他故事一律拒绝，已是新版则不操作。项目/章节/角色/音色ID保留，章节version递增。旧版规范定义保存在 `assets/story-packs/paint-prologue/release-v1.json`。安装/升级前检查美术路径、声音参考、对白文本/角色/语言/节点以及运行音轨SHA。

新环境先按主README完成依赖、Prisma与演示账号初始化，再执行本页seed。普通 `prisma db seed` 继续保留原有职责，新增序章使用独立命令，避免媒体未齐时创建半成品。

修改 `paintLines.ts` 后先重建domain并导出脚本，再按声音README重生成变更句、重新打包和检查；不能只更新 `textHash` 让旧音频看起来有效。美术再打包用 `node scripts/package-paint-art.mjs`，此命令读取仓库内原图，不需要开发者电脑的native路径；`--ingest` 仅供初次复制原生生成结果。

模型运行依赖、训练权重、数据库、用户副本和本机上传音频不入Git。保留以前的官方故事、页面主视觉和已有用户素材；新增素材只安装一次，删除后不会被每次打开素材库重新塞回。
