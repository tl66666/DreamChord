# DreamChord 官方示例剧情与声音导演设计

日期：2026-10-27  
状态：已确认方向，等待书面规格复核

## 1. 目标

把《第一根弦：消失的终页》从“展示节点功能的短 Demo”提升为一段约 12–18 分钟、具备完整悬念、角色弧光、有效分支和成熟声音演出的官方样板。同时将声音库从单次文本转语音工具升级为可服务任意项目的“配音导演”，让作者修改台词后仍能自动获得与角色、语义和场景匹配的候选配音。

本轮验收不以“生成出声音”为标准，而以正式播放器中的连续体验为标准：角色声音可区分，情绪与台词相符，音乐不抢对白，选择会改变后续内容，台词、声音、立绘和音乐共同完成演出。

## 2. 已确认的问题

当前官方示例包含 77 个节点、39 句对白和约 1265 个正文字符，但没有给任何节点绑定音乐、配音或效果音，也没有使用转场、字幕和停顿节点。第一次选择在各播放一句对白后立即汇合，没有持久状态；第七幕虽然声称早先选择改变了世界，实际播放内容并未根据选择发生变化。

现有三款起始音色来自单一合成参考，适合作为安装和链路验证，不适合作为正式角色选角。声音库虽然记录了 `emotion`，GPT-SoVITS Provider 请求只使用文本、参考音频、语速和随机种子，导致界面中的情绪标签没有真正影响推理。现有三首示例音乐是短时确定性程序合成，乐器层次、动态和段落变化不足，也没有与剧情建立具体对应关系。

## 3. 设计原则

1. **先导演、后生成**：台词先得到角色化的表演指令，再交给任意语音引擎。
2. **显式标注优先**：作者填写的情绪和表演指令高于自动判断，自动判断只负责提供可编辑默认值。
3. **不同引擎做擅长的事**：表达性配音和声音克隆不强行依赖同一个后端。
4. **选择必须产生可观察结果**：至少改变后续对白、角色关系、立绘、音乐或结局代价中的两项。
5. **素材必须可追溯**：记录来源、许可、哈希、作者和是否允许声音模型训练；不抓取未授权真人或商业角色声音。
6. **播放器体验是最终真相**：素材库试听好听但正式剧情割裂，仍视为未完成。

## 4. 官方示例剧情重构

### 4.1 核心设定

雪是轻小说部主笔，能够看见故事节点。社团审查将在 17:00 开始，最后一页却在 16:47 从稿件和所有备份中同步消失。被删除旧稿的主角“影”、记录现实变化的学姐“宫”、从空白节点醒来的“空”以及由删除记录和自动保存碎片形成的“系统幽灵”共同卷入事件。

终页并不是一句遗失的结局，而是一项被雪删除的选择：旧结局要求空作为一次性剧情工具消失，才能让作品获得工整收束。系统幽灵一直阻止恢复旧终页，不是因为系统故障，而是它在历次删除记录中学会了保护那些没有机会开口的角色。

### 4.2 九幕结构

#### 第一幕：稿纸归零

- 以 16:47 倒计时和正在消失的文字冷开场。
- 雪试图复制最后一句，文字却从剪贴板、打印稿和黑板上同步消失。
- BGM 在异常发生前保持日常，首个文字消失音效后立即抽掉旋律。
- 系统幽灵只报告现象，不解释主题。

#### 第二幕：教室残响

- 雪强行恢复一个断裂节点，宫随即忘记两人共同写过的开场句。
- 桌上的便签仍保留宫的笔迹，形成“记忆消失但物证存在”的悬念。
- 雪第一次意识到修改故事正在影响现实。

#### 第三幕：樱花路上的影子

- 影拿出雪两年前的旧稿，不直接讲自己是谁，而是准确接出只有旧主角知道的下一句。
- 玩家第一次选择雪面对失败的方式：承认恐惧、要求重写、交还角色选择权。
- 选择写入 `authorStance`，取值分别为 `fear`、`rewrite`、`agency`。
- 三条路线各有至少两句独有对白、一次不同表情和一个不同的短音乐提示，然后汇合。

#### 第四幕：咖啡馆的两种笔迹

- 宫通过便签和离线打印稿证明自己参与过结局创作，却从未出现在署名中。
- 雪承认自己在收到退稿后删除了所有版本，但不确定为什么连宫的署名也一同删除。
- 冲突从“雪害怕失败”扩展为“作者是否有权替共同创作者和角色决定什么值得留下”。

#### 第五幕：星弦空间

- 空以断续、缺词的方式出现；她的立绘和声音在句间逐渐稳定。
- 系统显示恢复旧终页的代价：空会被写回一个只负责牺牲的结局工具。
- 影希望恢复旧稿证明自己存在过，宫反对用另一个角色的消失证明现实。

#### 第六幕：命名

- 雪给空命名并非单方面赐予身份，而是先询问她想保留哪个字。
- 命名完成时，雪自己的名字短暂从学生证上消失，展示“赋予身份会占用现实锚点”的代价。
- 系统幽灵第一次违反系统报告格式，主动提醒雪停止恢复。

#### 第七幕：分支回响

- 根据 `authorStance` 进入三段真实不同的回响：
  - `fear`：雪承认自己仍想逃跑，影第一次不再讽刺她。
  - `rewrite`：雪提出重写规则，宫要求所有修改保留历史。
  - `agency`：空先提出自己的结局条件，雪选择只记录不替她回答。
- 三段使用不同立绘、情绪配音和短音乐变奏，再汇入终页选择。

#### 第八幕：写下终页

- 系统幽灵揭示自身由自动保存、批注和删除记录构成，因此它记得所有人被删掉的版本。
- 三个最终选择继续保留：让失败成为下一章、共同署名、让故事中的人决定。
- 选择文案同时说明即时代价，避免只有抽象价值判断。

#### 第九幕：日落之后

- 三条结局不互相汇合。
- “保留失败”：审查未通过，但获得一周重写期；雪公开保存退稿记录。
- “共同署名”：完整稿被接收，所有成员必须公开修改记录并承担共同责任。
- “角色自治”：作品以开放邀请形式通过，空选择留下，但她的未来不再由雪预写。
- 每个结局使用同一主题音乐的不同收束方式，使选择既有差异又保持作品统一。

### 4.3 文本与节奏规则

- 单句对白原则上控制在 12–36 个汉字，长解释拆成动作、反应和追问。
- 每个设定信息先由可观察事件出现，再允许角色解释。
- 每幕至少包含一种非对白演出：停顿、字幕、音效、音乐变化、表情变化或画面转场。
- 系统幽灵保持简洁、可量化的表达，直到第八幕才出现明显人格化语言。
- 不使用角色直接概括作品主题的台词；主题通过选择和代价呈现。

## 5. 声音系统

### 5.1 双引擎架构

声音库继续提供统一界面，底层支持多个 Provider：

- **CosyVoice 3**：官方 Demo 的默认表达性语音引擎。用于根据自然语言表演指令控制情绪、速度、音量和方言，并提供中文零样本音色。
- **GPT-SoVITS**：用于作者上传授权录音后的音色克隆、角色微调和已有音色兼容。
- **手动上传**：专业声优或后期制作的最终成品始终可以直接替换生成候选。

Provider 对外统一暴露健康检查、能力声明和生成接口。能力声明至少包含：`voiceClone`、`instructionEmotion`、`emotionReference`、`speedControl`、`seedControl`、`streaming`。导演层只请求能力，不在界面里散落引擎判断。

RTX 4060 Laptop 8GB 作为本机目标配置。CosyVoice 安装在独立运行时目录，不与 GPT-SoVITS 共用 Python 环境，避免依赖冲突。模型和生成缓存不提交 Git。

### 5.2 五个角色的选角方向

| 角色 | 声音方向 | 情绪弧线 |
| --- | --- | --- |
| 雪 | 17 岁左右的清亮女声，不卖萌，近距离、自然呼吸 | 慌乱克制 → 羞愧 → 决断 → 放松 |
| 影 | 年轻偏低男声，语句短，怒意被压住 | 冷硬 → 受伤 → 试探信任 |
| 宫 | 温暖可靠的青年女声，节奏稳定 | 日常温柔 → 迟疑 → 坚定追责 |
| 空 | 轻、通透的青年女声，初期断续 | 好奇疏离 → 害怕消失 → 主动选择 |
| 系统幽灵 | 中性合成声，清晰、低情绪 | 机械报告 → 犹豫 → 首次主动请求 |

系统幽灵允许保留可感知的合成质感，其他四人不使用同一基础音色简单变速伪装。

### 5.3 台词导演数据

每个对白节点可保存：

```ts
type VoiceDirection = {
  emotion: 'neutral' | 'warm' | 'joy' | 'sad' | 'tense' | 'angry' | 'afraid' | 'resolve' | 'whisper'
  intensity: number
  pace: number
  pauseProfile: 'short' | 'natural' | 'dramatic'
  delivery: string
  lockedFields: string[]
  source: 'manual' | 'auto'
  textHash: string
}
```

`textHash` 用于检测台词修改。文字变化后旧配音显示“台词已变化”，不会被静默当作最新成品继续使用。

### 5.4 自动适配流程

自动声音导演按以下顺序工作：

1. 读取角色默认声线、当前场景、相邻对白和明确舞台指令。
2. 使用确定性规则识别问句、省略、感叹、否定、迟疑、威胁、安慰和决心等信号。
3. 结合剧情节点已有的显式情绪，生成强度、语速、停顿和一句简短表演说明。
4. 保留作者锁定字段，只更新未锁定字段。
5. CosyVoice 将表演说明转换为推理指令；GPT-SoVITS 从同一音色的情绪参考池中选择最接近的参考片段，并调整语速和切句。
6. 无法可靠判断时回退到角色的自然音色，不随机夸大情绪。

因此用户输入任意新台词后可以自动适配，但系统会明确标注这是“自动导演候选”，作者仍能试听和覆盖。不会宣传为百分之百理解台词。

### 5.5 声音库和配音导演界面

- 声音库保留女娲式筛选、试听和卡片浏览。
- 每张音色卡增加角色适配、引擎能力、情绪覆盖和授权状态。
- 提供固定试听句 A/B 对比，避免不同文案造成错误判断。
- 新增“章节配音导演”：按角色分组显示未配音、生成中、待审核、已通过和文字已变化。
- 支持整章生成，但默认只生成候选；作者确认后才写入正式播放节点。
- 正式音频素材保存生成参数、参考来源、文本哈希、使用引擎和审核状态。

### 5.6 音频质量检查

生成完成后检查：

- 文件是否可解码；
- 峰值是否削波；
- 平均响度是否明显偏离项目目标；
- 开头和结尾是否存在异常长静音；
- 时长是否与文字长度严重不符；
- 是否出现全静音或极短结果。

未通过检查的结果保留为失败候选，不自动绑定剧情。通过技术检查仍不等同于表演通过，最终需要作者试听确认。

## 6. 音乐与效果音

### 6.1 素材策略

删除当前三首程序合成音乐作为官方 Demo 正式配乐的角色，但保留生成器作为测试和离线占位工具。正式配乐从同一位作者、同一素材包中选择，以维持乐器和混音一致性。

首选 TERNOX 的 Visual Novel Music Pack：21 首、人工作曲、CC0、允许商业使用。下载后保留原始许可页快照、来源 URL、文件哈希和作者信息。仓库内使用经过响度整理和体积压缩的 OGG；原始无损文件放在本地素材缓存，不进入 Git。

### 6.2 剧情配乐表

| 用途 | 场景 | 方向 |
| --- | --- | --- |
| 黄昏主题 | 标题、第一幕前半、结局回归 | 钢琴或木吉他，温暖但带未完成感 |
| 删除残响 | 第一幕异常、第二幕 | 稀疏氛围，弱低频，不持续铺满 |
| 影的旧稿 | 第三幕、第七幕 fear | 克制低音与脉冲，不做夸张恐怖 |
| 咖啡馆锚点 | 第四幕、第七幕 rewrite | 温暖日常配器中保留轻微不稳定音 |
| 星弦与空 | 第五至六幕、第七幕 agency | 通透钟琴、柔和 Pad、较大空间感 |
| 终页主题 | 第八至九幕 | 与黄昏主题音色统一，按结局选择不同收束 |

### 6.3 播放规则

- BGM 跨对白持续，不在每个节点重新启动。
- 场景换曲采用 800–1600ms 交叉淡化。
- 配音播放时 BGM 自动降低约 5–7dB，配音结束后平滑恢复。
- 进入选择时不强制停止配音；若玩家提前前进，当前配音立即淡出。
- 关键揭示前允许 0.4–1.2 秒静默，不用音乐填满全部时间。
- SFX 使用独立通道，文字消失、纸张、节点连接、倒计时和保存写回各自只使用少量稳定音色。

## 7. 数据流

```text
作者编辑台词
  → 自动声音导演分析
  → 作者检查或覆盖 VoiceDirection
  → Provider 能力路由
  → 生成候选
  → 技术质量检查
  → 作者试听确认
  → VOICE 素材
  → 写入 dialogue.audio.voice
  → 正式播放器按 BGM / VOICE / SFX 三通道播放
```

官方 Demo 种子数据使用稳定素材键，不写死个人机器绝对路径。种子脚本根据音乐清单和配音清单建立素材，并把 URL 写入对应剧情节点。重复执行必须幂等。

## 8. 失败处理

- CosyVoice 不可用时，声音库继续工作并显示具体缺失项；可以切换 GPT-SoVITS 或手动上传。
- GPT-SoVITS 没有匹配情绪参考时回退到自然参考，并在候选上标注“情绪参考回退”。
- 音乐文件缺失时正式播放器保持静默，不使用蜂鸣器或随机占位声破坏剧情。
- 批量生成允许部分成功；失败台词可单独重试，已经审核的结果不会被覆盖。
- 剧情文本变化后旧音频仍可试听和回滚，但默认不再作为发布版本。

## 9. 测试与验收

### 9.1 自动化测试

- 官方剧情仍有九个命名场景且无断线、死循环和空对白。
- 第一次选择写入三种不同状态，第七幕能据此进入三条不同内容。
- 三个最终结局互不汇合，且包含不同对白和音频方向。
- 自动声音导演对疑问、迟疑、愤怒、悲伤、决心和普通陈述给出稳定结果。
- 手动锁定的导演字段不会被自动分析覆盖。
- 修改台词后旧配音被标记为过期。
- Provider 能力不足时正确回退并保留原因。
- 音频质量检查能识别空文件、削波、长静音和异常时长。
- 音乐跨对白保持，换曲淡化，配音时自动压低 BGM，提前前进会停止旧配音。
- 音乐和声音种子重复运行不产生重复素材。

### 9.2 人工验收

1. 从标题开始完整通关三次，分别选择三个第一幕立场和三个结局。
2. 五个角色在不看名字时仍能通过声音方向区分。
3. 同一角色的不同情绪听起来仍是同一个角色，而不是五个不同音色。
4. 修改一条台词后，系统能自动重新给出合理的表演候选。
5. 配音可懂度、响度和停顿稳定，没有明显电子爆音、吞字或背景底噪。
6. 音乐不会盖住台词，关键反转处有刻意留白，场景切换没有硬切爆音。
7. 素材库能查到所有正式音乐和声音的来源与许可。

## 10. 实施边界与顺序

本轮只把官方 Demo 做成完整样板，同时把过程中形成的声音导演能力做成通用模块。不在同一轮建设在线计费、多租户 GPU 调度、实时数字人或未经审核的自动发布。

实施顺序：

1. 重构官方剧情与分支状态；
2. 增加 `VoiceDirection`、文本哈希和自动导演；
3. 安装并接入独立 CosyVoice 运行时，保留 GPT-SoVITS；
4. 下载、审听、登记并压缩人工作曲和效果音；
5. 为五名角色建立正式音色和情绪候选；
6. 批量生成官方 Demo 配音并人工筛选；
7. 把音乐、配音和效果音绑定到剧情节点；
8. 完善播放器淡化、压低 BGM 和提前跳句行为；
9. 完整三路线验收并更新使用文档。

## 11. 明确不做

- 不从动画、游戏、主播或声优作品中截取声音训练或克隆。
- 不把 CC0 的普通语音素材自动解释为允许声音模型训练；只有许可明确允许或录音者明确授权时才进入克隆流程。
- 不用不同语速把同一个音色伪装成五个正式角色。
- 不把自动情绪识别描述为绝对正确。
- 不让模型安装失败阻断编辑器的剧情、素材和手动上传能力。
