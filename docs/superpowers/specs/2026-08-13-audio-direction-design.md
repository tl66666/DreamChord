# DreamChord 音频演出设计

## 目标

让每个 DreamChord 项目都能从全局素材库选择 BGM、音效和配音，并在镜头卡中以结构化方式编排，在完整播放器、项目备份和 Agent 盘点中获得一致结果。

## 取舍

参考 WebGAL 的 BGM 持续、语句配音与独立音效通道，但不引入第二套脚本语言。DreamChord 的镜头卡已经是创作入口，因此音频配置作为镜头数据的一部分保存，由运行时解释。

本轮不实现在线 TTS、自动音频生成、波形剪辑器、字幕逐字同步或多轨时间线。这些能力需要外部服务、版权策略或精确时间模型，不能伪装成当前已经可靠的功能。

## 数据模型

所有音频引用均保存为上传或内置资源 URL，不保存浏览器临时对象 URL。

- `audio.bgm`：`keep`、`play`、`stop` 三种动作；`play` 可指定 BGM URL 和可选音量，淡入/淡出字段为后续兼容预留，当前播放器尚不自动执行渐变。
- `audio.sfx`：零个或多个一次性音效 URL，每项带音量。
- `audio.voice`：对话或旁白可选的一段配音 URL，带音量；没有 URL 时播放器不播放配音。

不选择音频时，旧项目的节点数据保持兼容；没有音频字段的镜头不会触发任何音频事件。

## 编辑与素材工作流

素材库将音频明确分为 `BGM`、`SFX`、`VOICE`。三者均使用已有服务端媒体验证、全局复用、重命名、替换、删除与项目备份流程。

镜头卡的“音频演出”区域提供：

1. BGM 保持、播放/切换或停止；作品级音量在播放器设置中控制。
2. 多个一次性音效选择。
3. 对话/旁白的单段配音选择。

音频选择器只展示音频类型，不能误选图片；配置保存在当前镜头卡并走现有自动保存与版本冲突保护。

## 播放器运行时

播放器使用三个独立通道：一个循环 BGM 元素、一个配音元素、按需创建的音效元素。

- 同一 BGM 的 `keep` 或重复 `play` 不重启播放。
- 切换 BGM 时停止旧曲，再启动新曲；浏览器拒绝自动播放时保留静默状态，不中断剧情操作。
- 进入新镜头、选择分支、重新开始、离开页面时停止过期配音与音效；BGM 只在明确停止、切换或页面卸载时停止。
- 设置面板保留 BGM、音效和配音三组音量，静音设置不修改作品数据。

## Agent

Agent 的素材读取工具包含 BGM、SFX、VOICE。无 Key 本地助手可盘点音频素材，并根据章节节点给出“缺少 BGM、关键音效或配音”的需求清单；它不会自动选择、绑定或替换音频。未来外部模型可以生成音频需求提案，但仍必须由作者在镜头卡确认。

## 验证

- 转换器测试确认镜头节点把 BGM、SFX 与配音映射到运行时场景。
- 播放器音频控制器测试确认保持、切换、停止、音量和清理行为。
- 编辑器测试确认选择器只接受匹配的音频类型。
- 项目导入导出测试确认节点内的音频 URL 随现有深度资源重映射保留。
- 完整 lint、测试、构建、就绪检查、浏览器验收与 GitHub CI 必须通过。
