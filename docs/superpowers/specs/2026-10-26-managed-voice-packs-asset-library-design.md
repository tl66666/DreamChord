# DreamChord 托管声音包与宽屏素材库设计

日期：2026-10-26

## 目标

本轮在既有私有声音库和 GPT-SoVITS Provider 上完成两项升级：

1. 让没有 Python/Conda 经验的作者只执行一次项目命令，就能安装并由 DreamChord 托管本机声音引擎；日常不需要打开 GPT-SoVITS WebUI。
2. 重构素材库的大屏信息架构，解决当前 1280px 最大容器造成的屏幕浪费，以及角色卡片中立绘过小、长名称破碎、设定信息拥挤的问题。

同时提供三套可追溯、许可明确的 DreamChord 官方体验音色，让首次使用者可以立即理解角色绑定、试听生成和成品入库流程。

## 工作拆分与顺序

本轮分成两个可独立验收的子项目，按顺序实施：

1. **托管声音运行时与体验音色包**：先完成安装、启动、参考音频与声音库数据，确保真实推理可用。
2. **宽屏素材库**：再调整页面骨架与角色库交互，不让视觉改造干扰声音引擎排错。

## 1. 托管声音运行时

### 安装位置

当前 C 盘只剩约 30GB，D 盘剩余约 136GB。默认把大型运行时放在 `D:\DreamChordRuntime`：

- `D:\DreamChordRuntime\miniforge3`：项目专用 Miniforge；
- `D:\DreamChordRuntime\gpt-sovits`：GPT-SoVITS 源码、独立 Python 环境和预训练权重；
- 项目仓库只保存脚本、配置和小型元数据，不提交模型权重。

安装脚本仍允许用参数覆盖目录。它会把最终路径写入本地 `apps/server/.env`，应用层继续通过 `GPT_SOVITS_HOME` 查找引擎，所以“放在 D 盘”不会改变项目内一体化使用体验。

### 安装器行为

`pnpm voice:setup` 负责完整的一次性准备：

1. 检查 Git、PowerShell、磁盘和 NVIDIA 显卡；
2. 没有 Conda 时，从 conda-forge 官方 Miniforge Release 下载 Windows 安装包；
3. 下载相同 Release 的 SHA256 文件并校验，不执行校验失败的文件；
4. 静默安装到 DreamChord 专用目录，不写系统 PATH、不注册为系统 Python；
5. 克隆 GPT-SoVITS 官方仓库，创建独立环境；
6. 调用官方 `install.ps1` 安装 CUDA 12.6 依赖与预训练模型；
7. 验证 `api_v2.py`、推理配置、Python 和关键模型文件；
8. 写入本地配置并执行一次健康检查。

脚本可重复执行：已完成的下载和环境创建会被复用；失败后再次执行从最近的安全检查点继续。

### 日常启动

DreamChord 服务端继续使用 `ManagedVoiceEngine` 隐藏启动官方 `api_v2.py`，固定监听 `127.0.0.1`。浏览器只能请求启动、停止和健康状态，不能传入命令、路径或监听地址。退出 DreamChord 时只停止由当前进程创建的子进程。

## 2. 官方体验音色包

### 来源与许可

不使用从视频网站、主播、声优、演员或其他真实个人处抓取的声音。体验音色由 Apache 2.0 开放权重的 Kokoro 生成中文合成参考素材，再交给 GPT-SoVITS 做角色化零样本推理。每个音色在素材元数据和界面中记录：

- `sourceModel: hexgrad/Kokoro-82M`；
- `sourceLicense: Apache-2.0`；
- `syntheticSource: true`；
- 生成用 voice id、原文、语言、日期和文件哈希；
- “DreamChord 官方体验音色，不对应真实人物”的可见说明。

许可文件和来源说明随体验音色元数据保留。若下载内容的模型卡或许可与预期不一致，导入脚本立即停止。

### 三套音色

- **星璃・清澈**：年轻、明亮、适合校园日常和轻快对白；
- **雾岚・轻语**：柔和、克制、适合旁白和情感场景；
- **暮川・沉稳**：较低、稳定、适合悬疑角色和成年男性对白。

名字是 DreamChord 内部艺术命名，不使用底层模型 voice id 或任何真人姓名冒充角色品牌。

### 生成策略

第一阶段使用 GPT-SoVITS 官方推荐的零样本/少样本路径，不立刻为三个体验音色分别训练私有权重：

- 原因一：当前 Provider 使用一套全局权重，强行切换三套训练权重会显著增加状态管理和显存风险；
- 原因二：官方 V5 路线已强调无需 SoVITS 微调也能提高相似度，体验音色先以参考音驱动更稳定；
- 原因三：合成参考音可以立即提供准确逐字稿和明确许可。

这里的“声音克隆”是根据许可明确的合成参考音生成新台词；界面不把它误称为已经完成模型微调。后续真正的角色微调训练会作为独立训练队列设计，要求用户提供至少约一分钟已授权素材，并为每个档案记录权重版本。

### 导入与幂等

新增 `voice:seed` 脚本生成或下载参考 WAV，计算哈希，并把三套体验音色、参考素材和 `VoiceReference` 写入当前演示用户的私有声音库。重复执行按稳定 key 更新，不创建副本。删除体验音色后不在普通启动时自动恢复，只有手动再次运行 seed 才恢复。

## 3. 宽屏素材库

### 根因

现有页面使用 `max-w-7xl`（约 1280px），即使浏览器宽达 2560px 也会浪费两侧空间。角色区在约 1000px 内容宽度内强制双列；每张约 500px 的卡片又使用 170px 立绘列，导致名称、角色标签、说明块和操作按钮互相挤压。

### 页面骨架

- 页面最大宽度提升到约 1760px，并在超宽屏保留舒适边距；
- 侧栏宽度保持 220–240px，滚动时吸顶；
- 主内容区使用更轻的边界和分层背景，不再用一个巨大白色框包住所有内容；
- 小于 1024px 时侧栏改为顶部横向标签，小屏仍为单列。

### 角色库交互

采用“视觉画廊 + 选中详情”而不是把完整角色圣经复制进每张卡：

- 画廊卡以 4:5 大立绘为视觉中心，宽屏 3 列、中屏 2 列、手机 1 列；
- 卡片显示名称、定位、两行简介、表情数量和更新时间；
- 全身/半身/舞台切换直接作用于大预览；
- 点击卡片进入右侧详情抽屉（窄屏为底部全屏面板）；
- 详情区展示完整人物小传、故事大纲、戏剧冲突、项目用途、表情缩略图和编辑/删除操作；
- 长名称使用最多两行并保留完整 title，不再逐字挤成竖排；
- 删除、编辑、查看原图等次要操作从卡片头部移入详情或溢出菜单，降低视觉噪声。

场景库和全局素材沿用同一宽屏骨架，但本轮只重构角色卡，避免无关大规模改动。

### 视觉方向

延续 DreamChord 的柔和紫色品牌，但降低大面积紫色渐变。角色画廊采用接近视觉小说“角色图鉴”的编辑感：浅灰纸面、细线分隔、较大的角色名和有节奏的留白。图片区优先，文本信息通过层级而不是堆叠彩色块表达。

## 4. 数据流与错误处理

### 安装

安装脚本输出当前阶段、目标路径和可恢复错误。网络中断、校验失败、磁盘不足或官方脚本失败时，不修改“安装完成”配置。半成品目录可被下次运行复用，但 `ManagedVoiceEngine` 只有在 API、配置和 Python 都存在时才报告已安装。

### 音色包

体验音色导入前先验证 WAV 可解码、时长合适、文字稿非空、哈希匹配和来源许可。任何一项失败都不写数据库。数据库写入和文件复制作为一个可回滚操作处理。

### 素材库

详情抽屉没有选中项时不渲染；被选角色删除后自动关闭。不存在立绘时保留明确占位图和重新上传入口，不让破图撑坏布局。预览模式仍复用 `StageCharacters`，确保素材库与正式播放器的裁切规则一致。

## 5. 测试与验收

### 自动测试

- 安装器路径选择、官方校验文件解析、本地配置更新和重复执行；
- 运行时对完整/半成品安装状态的识别；
- 体验音色 manifest 的许可字段、稳定 key 和幂等导入；
- 角色画廊响应式列数、预览切换、详情打开/关闭、删除后状态；
- 原有声音生成、播放器与素材测试全部回归。

### 实机验收

- 在当前 RTX 4060 8GB 电脑上完成官方 GPT-SoVITS 安装并通过 `/api/voices/provider/health`；
- 三套体验音色出现在“素材库 → 声音库”，至少各生成一句可试听中文台词；
- 在 2560×1600、1440×900、390×844 三个视口检查素材库；
- 2560×1600 下不再出现大面积无用途留白，角色立绘显著大于旧版；
- 无横向滚动、名称竖排、操作遮挡或浏览器控制台错误。

## 非目标

- 不下载或克隆未经授权的真人声音；
- 不在正式 Galgame 播放过程中实时推理；
- 本轮不实现三套独立 GPT/SoVITS 微调权重和自动权重热切换；
- 不把大型模型、Miniforge 或生成音频提交到 Git。
