# DreamChord Galgame 播放器、立绘预览与官方 Demo 升级设计

日期：2026-10-23

## 目标

把 DreamChord 从“能播放剧情的创作工具”提升为“编辑时可准确预演、正式播放时具有成熟视觉小说质感”的一体化工作台。本轮保持现有章节、场景、镜头卡和故事图架构，重点完善三个直接影响体验的部分：

1. 正式播放器的舞台构图、对话界面、选项与操作反馈。
2. 角色库和编辑器对全身、半身及最终舞台效果的统一预览。
3. 官方演示剧情的节奏、人物关系、选择回响与结局展示。

本轮不照搬任何商业作品的素材或界面。参考成熟 Galgame 的信息层级、角色优先构图和低干扰操作逻辑，继续使用 DreamChord 的紫蓝、星弦、节点与发光连线作为自身视觉语言。

## 当前问题

- 正式播放器按全身比例缩放普通人物，脸部偏小，多人同屏时人物缺乏存在感。
- 播放器、编辑器实时预览和角色库分别实现立绘布局，裁切、缩放和说话者聚焦不一致。
- 对话框是大面积通用黑色横条，作品辨识度不足；旁白、心理、回忆和系统提示也没有足够清晰的演出差异。
- 选项接近普通表单，缺少进入、悬停、确认和键盘提示等剧情节点应有的反馈。
- 播放器顶部控件始终占据注意力，与沉浸式阅读目标冲突。
- 官方 Demo 的世界观核心清晰，但推进过快，第一次选择很快失去影响，第二次选择也立刻汇合。
- `DEMO_STORY.md` 与 `packages/story-domain/src/officialDemo.ts` 的剧情版本不一致。

## 设计原则

### 角色优先

普通人物在正式播放时默认采用腰部以上到大腿中部的半身构图，脸部位于上半屏视觉焦点。原始素材仍完整保存，角色库可以随时检查全身。系统幽灵等非人形或特殊比例角色保留完整展示。

### 所见即所得

正式播放器、实时预览和角色库的“舞台效果”必须复用同一套立绘布局规则。编辑器右侧看到的角色大小、裁切、站位和发言聚焦，应与正式播放保持一致。

### 界面退后，故事向前

对话、选择和当前说话者是第一层信息；历史、自动、跳过和设置是第二层工具。工具控件在静置时降低存在感，交互时恢复，不与角色面部和文本争夺注意力。

### 分支必须留下痕迹

选择至少应满足一项：改变后续台词、改变人物态度、揭示不同信息或进入不同尾声。仅改变一句台词后马上汇合，不作为官方 Demo 的主要选择展示。

## 方案范围

### 1. 共享舞台立绘系统

新增一个可复用的舞台立绘组件，供正式播放器和编辑器实时预览使用。组件接收：

- 角色 ID、图片地址、表情、站位；
- 同屏角色数量；
- 当前发言者；
- 展示模式：`full`、`bust`、`stage`；
- 角色类别：普通人物或特殊角色。

展示规则：

- `full`：完整显示原图，用于角色素材检查。
- `bust`：单人半身裁切，用于表情和面部细节检查。
- `stage`：使用正式播放器布局，包含多人站位、说话者聚焦和对话框安全区。
- 普通人物在正式播放器中使用 `stage` 半身构图。
- 系统幽灵使用特殊角色规则，保持完整轮廓，不强制截到腰部。
- 单人居中；双人左右分布并朝向画面中心；三人左、中、右分布并适当降低宽度。
- 当前说话者保持正常亮度并轻微前移；其他角色降低亮度和饱和度，但仍可辨认表情。
- 表情变化采用短交叉淡化，登场与退场使用轻微纵向位移，不使用夸张弹跳。

组件不修改原始图片，不为半身模式生成重复文件。裁切仅属于展示层。

### 2. 正式播放器

#### 舞台层

- 背景维持全屏 cover，并增加轻微暗角与底部可读性渐变。
- 普通角色放大为半身视觉比例；角色头顶不得被裁切，面部不得被顶部控件覆盖。
- 对话框遮挡区作为舞台布局的一部分计算，不让人物关键表情落入文字区域。
- 背景切换采用柔和淡入；角色换表情采用局部交叉淡化，避免整个舞台闪烁。

#### 对话层

使用“星弦玻璃”视觉：深色半透明玻璃、细窄角色色高光、低对比星点纹理和独立姓名签。整体避免纯黑大块压住背景。

- 角色对话：显示姓名签和角色主题色。
- 旁白：不显示角色姓名，文本区域略收窄并使用更克制的排版。
- 心理描写：使用轻微斜体或柔和光晕，但保持可读性。
- 回忆：增加低饱和边框与时间感标识。
- 系统提示：使用节点标签样式，与系统幽灵和 DreamChord 品牌语言一致。
- 继续指示器位于文本右下角，打字完成后才出现。

#### 选项层

- 选项位于画面中下部，对话框上方，背景轻微压暗。
- 每项包含序号、正文和清晰的悬停/聚焦状态。
- 支持鼠标点击及数字键选择。
- 选中后短暂显示确认反馈，再进入下一镜头。
- 自动与跳过模式遇到选项时停止。

#### 工具层

- 将返回、历史、自动、跳过、设置整理为左右两个低干扰控制组。
- 鼠标或键盘静置时降低透明度；移动、聚焦或模式启用时恢复。
- 自动、跳过必须有文字状态提示，不能只靠颜色区分。
- 历史面板保留角色色和台词，可滚动查看；不在本轮增加从历史跳回剧情。
- 设置继续支持文字速度、BGM、音效和语音音量。

#### 响应式规则

- 1440×900：完整舞台、宽对话区、左右控制组。
- 1024×768：收紧边距和立绘宽度，但仍保持半身构图。
- 430×932、390×844：对话框高度随文本内容约束；角色面部位于屏幕上半区；控件改为紧凑图标栏；选项允许独立滚动。

### 3. 角色库与编辑器预览

#### 角色库

角色卡保留完整人物预览，并增加三个预览切换：

- 全身：检查脚部、手部、透明边缘和整体比例。
- 半身：检查正式对话时的脸部与上身效果。
- 舞台：在背景、安全区和对话框遮挡条件下检查最终表现。

表情列表继续可点击切换。预览切换属于界面状态，不改变素材文件，也不改写角色数据。

#### 编辑器实时预览

- 复用共享舞台组件和正式播放器的站位算法。
- 当前发言者自动成为焦点，其他角色执行相同的降亮度规则。
- 显示对话框安全区，作者能直接判断人物是否被遮挡。
- 保留场景代码、镜头类型和完整预览入口，但降低标签的视觉重量。
- 空台词、缺背景和图片加载失败仍提供明确状态，不让预览区域崩溃。

### 4. 官方演示剧情

正式运行版本以 `officialDemo.ts` 为唯一行为来源，`DEMO_STORY.md` 同步为相同剧情说明。

保留现有核心：雪为了在日落前找回被自己删除的终页，重新面对影、宫、空以及自己的创作恐惧。

剧情调整为四段：

1. **钩子：稿纸归零**
   - 用倒计时和正在消失的最后一页立即建立目标。
   - 增加一小段雪试图阻止文字消失但失败的动作与心理，让危机先被感受到，再由系统幽灵解释。

2. **追索：被放弃的选择**
   - 樱花路上的影不直接进行大段设定说明，而是通过他记得旧稿内容、雪却记不清的冲突揭示身份。
   - 第一次选择分别代表“承认恐惧”“请求重写”“把选择交还角色”。
   - 三条路线各提供不同信息和影的不同态度，再回到咖啡馆主线。

3. **命名：让空白开口**
   - 宫提供现实记录并指出删除行为的真实代价。
   - 空的命名不只是一句宣言，而是一次关于“作者是否拥有角色全部决定权”的对话。
   - 系统幽灵的提示保持简短，只在节点、分支和保存等关键动作出现。

4. **终页：承担自己的答案**
   - 最终选择不再立刻汇合，而是进入三个短尾声：接纳失败、共同署名、交还选择。
   - 每个尾声都有不同角色回应和一条独立收束句，均回扣第一次选择的主题。
   - 结尾回到教室，确认轻小说部保留，但不把结果写成毫无代价的完美胜利。
   - 最后一幕自然引导玩家返回工作台，而不是使用突兀的营销 CTA。

目标试玩时长为 10–15 分钟。使用现有四张背景和现有角色表情，不依赖本轮新增绘画素材。

### 5. 数据与架构

- 不更改原始立绘文件，不为半身显示新增重复素材。
- 普通人物/特殊角色的默认表现优先由现有角色注册表决定；未知自定义角色默认按普通人物处理。
- 共享舞台组件只负责视觉展示，不复制故事状态。
- `useEditorStore` 继续作为编辑器唯一图状态来源。
- 正式播放器仍由运行时引擎推进剧情，界面层不自行维护第二套剧情分支。
- 最终选择使用已有图边连接到三个独立终点，不新增路线变量系统。

## 错误与降级处理

- 立绘加载失败：保留角色站位并显示低干扰占位符，不能让布局跳动。
- 背景加载失败：显示深色星弦占位背景，并保留对话可读性。
- 未知角色：使用项目角色名称和默认主题色；没有匹配立绘时使用默认头像。
- 超长台词：对话区在桌面限制最大高度，在移动端允许内部滚动，继续按钮始终可达。
- 选项过多或过长：选项容器滚动，数字快捷键仅对应前九项。
- 动画偏好：遵循 `prefers-reduced-motion`，降低位移和缩放，只保留必要淡入淡出。

## 测试与验收

### 自动化测试

- 共享舞台布局：单人、双人、三人站位；普通人物与特殊角色模式；说话者聚焦。
- 角色库：全身、半身、舞台三种预览可切换，表情切换继续有效。
- 编辑器预览：舞台状态、发言者和立绘 URL 与镜头卡一致。
- 播放器：选项出现时停止自动/跳过；数字键可选择；不同最终选项进入不同终点。
- 官方 Demo：所有节点可达、三个最终分支各自终止、没有断路或意外死路。

### 浏览器验收

- 1440×900、1024×768、430×932、390×844 四组尺寸。
- 检查普通人物为半身构图，系统幽灵保持完整展示。
- 检查姓名、台词、选项、控制区和人物面部没有重叠。
- 检查角色库、实时预览和正式播放器的舞台效果一致。
- 完整试玩三个尾声，确认历史、自动、跳过和设置可用。
- 检查控制台错误和失败网络请求。

## 不在本轮范围

- 多槽位存档、读档和云同步。
- 从历史记录跳回任意剧情节点。
- 路线好感度、变量条件和复杂条件分支。
- Live2D、口型同步、逐字语音同步。
- 新角色、新背景或重新生成现有美术素材。
- 在线发布流程与多人协作。

这些能力可以在共享舞台系统稳定后继续扩展，不应阻塞本轮体验升级。
